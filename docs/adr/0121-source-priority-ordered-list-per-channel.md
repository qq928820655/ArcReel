# 多源优先级：按通道的有序来源列表，额度耗尽或连不上时下移、每日零点重置

单模型配置表达不了「首选这家、用完再换那家」的诉求：用户当前只能手动改默认模型，或让生成在额度耗尽时直接失败。决定为视频 / 图片 / 文本三条通道各加一份**有序的 `(provider, model)` 列表 + 独立开关**，取代该通道的默认模型配置：当前来源连续两次额度不足、或连续五次连不上时下移一行，每天北京时间零点回到首行；开关关闭时整条链路不参与解析，行为与没有这个功能完全等价。

## 数据分层

配置与运行态分开存放，读写频次相差两个数量级：

- **配置**（开关 + 有序列表）：低频写、参与模型引用扫描。全局落 `system_setting` 的 `source_priority_<media>` 键（值为 JSON），项目落 `project.json` 的 `source_priority` 字段。走既有配置通道，不新建表。
- **运行态**（当前第几行、连续几次额度不足、连续几次连不上、最近一次重置日期）：高频易变，落独立表 `source_priority_state`（主键 `(scope, project_name, media_type)`）。不回写 `project.json`——那是被高频热读的文件，每次失败回调改它都会牵动缓存与变更提示。

解析顺序与既有四级骨架一致：项目层有配置且开启时用项目的列表，否则回落全局；两层都未开启时返回 `None`，调用方照原样走既有解析。

## 额度耗尽的判定

「额度不足」的判据宁可漏判不可误判——误判会在用户不知情时换源，多花一份钱：

- HTTP 402 恒判为额度不足（唯一无歧义的码）。
- 5xx 一律排除（服务端故障不是额度问题）。
- 裸 429 不算：它同时表示速率限制，偶发限流下换源会打乱用户排好的顺序。
- 其余状态码只在响应文本命中额度关键词（`quota exceeded`、`insufficient_quota` 等）时才算。
- 要求**连续两次**才下移：单次失败不足以证明额度确实用完，阈值 2 是最小可信信号；任一成功清零 streak。
- 已到末行仍额度不足：停在末行、streak 保持，次日零点整体重置。

## 连不上供应商的判定

另一类触发是「连不上当前来源」——不是额度问题，但继续用这个源只会每次都失败。判定范围严格限定在**连接上游模型供应商的握手阶段**：

- 只收连接建立类传输错误：`ConnectError`、`ConnectTimeout`、`PoolTimeout`、`ProxyError`。这些代表请求确定没送到供应商，换源不会重复计费、不会留下孤儿任务。
- **不收**读超时 / 写错误 / 中途断连（`ReadTimeout`、`WriteError`、`RemoteProtocolError` 等）：请求可能已被供应商接收，此时换源会导致重复计费或轮询到别家的任务。
- 与下游工具请求的网络异常无关：那些请求不经过这条解析路径。
- 阈值**连续五次**，比额度的两次更宽——连接失败可能是本机抖动、DNS 临时故障或供应商入口短暂不可达，单次不足以判定该源长期不可用。阈值可由环境变量 `ARCREEL_SOURCE_PRIORITY_NETWORK_THRESHOLD` 覆盖（正整数，非法值回落默认）。
- 与额度**分开计数**：合并计数会让「几次额度不足 + 几次断网」凑够阈值而误切。任一计数达到各自阈值即下移一行，并把两个计数一起清零（换到新源，两者都从头开始）。

## 每日重置

重置是**日期粒度**的幂等动作，不是「每隔 24 小时」：

- 运行态表带 `last_reset_on`，`reset_if_due` 以它与今天（北京日期）比较，同一天重复调用不重复推进。
- 进程不保证零点在线，故两条路径都走同一函数：启动时先补一次（停机跨过零点后应当已经回首行），常驻循环等到下一个北京零点再跑。

## 本期接入范围

只把**视频**通道接进解析（`WIRED_MEDIA_TYPES={"video"}`）。图片与文本的配置可以保存、可以在界面里预览，但生成链路尚未接入；此时推进它们的运行态只会让界面显示的「当前源」与实际执行不一致，故服务层按媒体类型过滤，只推进已接入的通道。

## 明确不采用

- **运行态存 `project.json`**：见上，热读文件不适合承载高频变更。
- **一次性失败就换源**：偶发限流会被当成额度耗尽，顺序失去意义。
- **额度不足时静默降到无配置**：换到末行也用完时应当停在末行并如实呈现，而不是悄悄回退到默认模型——那会让用户以为仍在按列表执行。
- **续跑任务也按当前行重解析**：续跑的身份来自提交时冻结的检查点，换源会导致轮询到另一家厂商的任务。多源解析只在「按当前配置新提交」的路径生效，payload 锁定与续跑在更早处分流。
- **能力不满足时换行**：换行是额度耗尽才做的事。配置里的模型不具备该桶能力时直接报错，让用户看见并改配置。

## Consequences

- 模型引用扫描（`project_model_references`、`_referenced_models`）把多源列表里的每一行都算作引用：删除模型时确认框会列出引用了它的项目与全局配置，避免删掉仍在列表里的模型。
- 列表改短后运行态下标可能越界，消费方一律经 `clamp_active_index` 夹到 `[0, len)`，回落到末行而不是报错。
- 前端呈现：全局设置与项目设置各有一个「多源优先级」分区，三条通道共用一套编辑器（开关 + 可增删排序的列表 + 点选当前行）。项目层未配置的通道展示全局那份并标注回落，避免展示与执行不一致。
- 项目层的运行态按项目作用域记；项目层未配置而回落全局时，该通道的运行态记在全局作用域下，故回落的通道直接读全局运行态。
